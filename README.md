# Bygg og Renovering Vest – byggrv.no

A static Next.js 16 site (App Router, TypeScript, Tailwind v4) for Bygg og Renovering Vest AS, Bergen. Style "Lys papir": light paper pages, with only the hero and the "Slik bygger vi" sequence on a dark stage. A React Three Fiber model of an architect-designed reference house builds itself layer by layer as you scroll. GSAP ScrollTrigger and Lenis drive the scroll animation.

Design rules are in `DESIGN.md`. Decisions made with the client are in `HANDOFF.md`. The client's original brief is `docs/byggrv-prompt.md`.

## Run

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # static export to ./out
npm run lint
```

Preview the static build with any file server, for example `npx serve@14 out` or `python3 -m http.server --directory out 3000`.

## Deploy (Vercel)

1. Import the repository in Vercel and pick the branch.
2. Keep the framework preset **Next.js**. The build command is `next build`. Because of `output: "export"` (in `next.config.ts`, with `trailingSlash: true` and unoptimised images), the result is a fully static site in `out/`. No server functions are used.
3. Add the environment variable `NEXT_PUBLIC_FORM_ENDPOINT` (see below) for Production and Preview, then deploy.

`out/` can also go to any static host (Netlify, Cloudflare Pages, S3/CloudFront, nginx).

### Contact form: `NEXT_PUBLIC_FORM_ENDPOINT`

Set `NEXT_PUBLIC_FORM_ENDPOINT` at build time to a form service that forwards to post@byggrv.no, for example `https://formspree.io/f/xxxxxxx` (see `.env.example`). The form POSTs JSON (`navn, telefon, epost, prosjekttype, adresse, melding`) there and shows a success or error state.

Without the variable, the form opens a prefilled e-mail to post@byggrv.no and says so, and the page shows `[MANGLER: skjematjeneste]` under the form. The variable name is only documented here, never shown to visitors. Remember to update the privacy page (`src/content/privacy.ts`) with the name of the form service and the data processing agreement.

| `src/lib/` | SEO/metadata and JSON-LD (GeneralContractor) helpers, fonts, motion, hooks, contact form logic, image types. |
| `src/components/ui/` | Primitives (Section/SectionHeader, RevealText, MagneticButton, BeforeAfter, Picture, Missing …). |
| `src/components/providers/` | SmoothScroll (Lenis + ScrollTrigger, hash-link focus) and RevealObserver. |
| `src/components/three/` | `HeroHouse`, `BuildSequence` ("Slik bygger vi"), `PermitDiagram` (R3F). |
| `src/components/sections/`, `layout/`, `forms/` | Page sections, header/footer/mobile action bar, contact form. |
| `scripts/` | Image pipeline, 3D model builder and render harness (see `scripts/README.md`). |
| `public/models/`, `public/renders/` | Meshopt-compressed GLB models and AVIF/WebP renders. |
| `public/images/byggrv/` | The client's original images; optimised copies in `opt/`. |
| `src/fonts/` | Newsreader and Schibsted Grotesk (Fontsource, self-hosted, trimmed). No runtime Google Fonts, no CDN scripts, no tracking. |

Performance notes: GSAP, ScrollTrigger and Lenis are not in the first page load. They load on the first interaction or when the browser is idle. Touch-only devices never load Lenis. All three.js code loads lazily near its section. The hero shows a poster image first (the LCP element); the canvas fades in later.

## 3D model and renders

```bash
npm run model:build                         # public/models/house.glb, house.meta.json, permits.glb (~3 s, deterministic)
NODE_PATH=$(npm root -g) npm run model:render                       # all stills → public/renders + src/content/renders.ts (~40 min, software WebGL)
NODE_PATH=$(npm root -g) npm run model:render -- --only=^svc-maling # a subset (regex on keys)
NODE_PATH=$(npm root -g) npm run model:render -- --preview=/tmp/p   # quick PNG previews only
```

The render harness needs Playwright (a global install is fine; `NODE_PATH=$(npm root -g)`) and a Chromium (`CHROMIUM_PATH`, `PLAYWRIGHT_BROWSERS_PATH` or `/opt/pw-browsers`). Camera and lighting presets live in `scripts/model/lib/cameras.mjs` (one source for renders and the live canvas). Shots, sizes and alt texts are in `scripts/render/shots.mjs`. Full details: `scripts/README.md`.

### Swapping in the client's own house model

The reference house is our interpretation of "House in Bergen" (Kvalbein Korsøen Arkitektur). To show one of the client's own houses instead, replace **`public/models/house.glb`** and **`public/models/house.meta.json`** with files that keep this contract:

- Root node `House`. Children are layer groups named exactly `layer_tomt`, `layer_grunnarbeid`, `layer_fundament`, `layer_bindingsverk`, `layer_isolasjon`, `layer_tak`, `layer_vinduer`, `layer_kledning`, `layer_installasjoner`, `layer_interior`, `layer_nokkelferdig` (Norwegian build order), each with `extras { step: "<id>", explode: [x, y, z] }`.
- Environment nodes `env_terrain`, `env_maple_a`, `env_maple_b`, `env_birch_*` (optional, but the stage expects the names if present).
- Materials named `glass` (window glass), `el_line` and `vvs_line` (the glowing installation runs), `lamp_glow` (warm lamps).
- `house.meta.json`: `bbox`, `floors[]` and `cutHeights[]` (plan cut), `layers.<id>` (`center`, `bbox`, `explode`), `hotspots.<stepId>[]` with ids matching `src/content/build.ts`, `camera.hero` / `camera.steps.<id>`, and `lighting` presets.
- Keep it Meshopt-compressed and under 3 MB.

The easiest path is to model the new house in `scripts/model/lib/` (same builder, same layer names) and run `npm run model:build && npm run model:render`. Then update the credit texts in `src/content/site.ts` (`referenceHouse`) and the reference-house section on `/om-oss/`.

## Client photos (image pipeline)

The text and images from byggrv.no are imported in `content-import/byggrv/` (page text as Markdown, `images.json` with source URL and page for each image). The 58 original images are in `public/images/byggrv/`, with their original filenames.

```bash
npm run images:build            # only rebuilds missing or outdated files
npm run images:build -- --force # rebuilds everything
```

`scripts/images/optimize.mjs` (sharp) reads `scripts/images/photos.config.mjs` and writes AVIF + WebP files to `public/images/byggrv/opt/` (`<key>-<width>`, capped at the original width), cleaned logo SVGs, and the typed manifests `src/content/photos.ts` (Norwegian alt text, size, sources, placeholder, caption, origin, source page) and `src/content/brand.ts`.

**To add a photo:** put the original in `public/images/byggrv/`, add an entry (key, Norwegian alt text, caption, `origin: "own"`) to `photos` in `photos.config.mjs`, run `npm run images:build`, then wire the key where it belongs: `photoKeys` of a service in `src/content/services.ts`, a before/after pair or `projectPhotos` in `src/content/references.ts`, or `photoKeys` of a reference (this replaces its `[MANGLER]` frame on `/referanser/`). The script stops if any image in `images.json` is not classified exactly once, so nothing reaches the site unreviewed. Own photos get a shared, slightly muted grade (`.photo-own`, DESIGN.md §5).
